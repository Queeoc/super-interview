# super-interview 前端编码规范

## 1. 文档目的

本文档用于约束 `frontend/` 独立前端项目的编码与协作方式，确保其与当前 Python 重构后的后端架构保持一致。该规范适用于后续 `React + TypeScript + Vite` 前端工程的所有新增代码。

目标如下：

- 保持前后端分层清晰
- 保持 API 对接稳定
- 控制状态管理复杂度
- 避免沿用旧 `static/` 的临时实现方式
- 为后续多人协作与持续演进提供统一标准

## 2. 基础约定

- 使用 `TypeScript`
- 文档、注释、必要代码说明优先中文
- 默认采用函数组件与 Hooks
- 禁止类组件
- 前端展示名保持 `super-interview`
- 所有新增业务能力默认写入新前端项目，不向 `static/` 继续堆功能

## 3. 命名规范

### 3.1 通用命名

- 组件名：`UpperCamelCase`
- hooks：`useXxx`
- TypeScript 类型：`UpperCamelCase`
- 枚举：`UpperCamelCase`
- 常量：`UPPER_SNAKE_CASE`

### 3.2 前端代码风格选择

前端项目统一采用 `camelCase` 命名：

- 变量名使用 `camelCase`
- 函数名使用 `camelCase`
- 普通模块名使用 `camelCase`

示例：

- `createInterviewSession`
- `submitInterviewAnswer`
- `streamEventDispatcher`

### 3.3 类型后缀约定

与后端 DTO 命名习惯保持对齐，前端类型统一采用以下后缀：

- `XxxDto`
- `XxxRequest`
- `XxxResponse`
- `XxxEvent`
- `XxxState`
- `XxxError`

示例：

- `InterviewSessionDto`
- `CreateInterviewRequest`
- `SubmitAnswerResponse`
- `InterviewStreamEvent`

### 3.4 API 文件命名

按业务域拆分 API 文件，禁止做成一个超大 `api.ts`：

- `interview.api.ts`
- `resume.api.ts`
- `skill.api.ts`
- `knowledge.api.ts`
- `health.api.ts`

## 4. 分层规则

推荐目录职责如下：

- `pages/`
  - 只负责页面编排
  - 组织页面布局、模块组合、路由参数衔接
  - 不直接写复杂请求与业务处理

- `features/`
  - 负责业务模块
  - 封装页面所需的领域逻辑
  - 例如：`interview`、`resume`、`knowledge`

- `components/`
  - 只放可复用 UI 组件
  - 不内嵌领域耦合逻辑

- `services/`
  - 负责 API 调用与 SSE 解析
  - 负责统一请求封装
  - 负责错误映射

- `types/`
  - 维护后端 DTO 的前端映射类型
  - 保证接口契约显式可读

- `hooks/`
  - 封装领域 hooks 与复用逻辑
  - 避免在页面中堆放重复副作用代码

禁止事项：

- 禁止页面直接散写 `fetch`
- 禁止组件内部拼接后端 URL 常量
- 禁止把业务逻辑堆进通用组件
- 禁止在 `components/` 中直接依赖某个具体页面路由

## 5. API 规范

### 5.1 统一请求入口

所有 HTTP 请求统一通过 `apiClient` 发起。

`apiClient` 必须负责：

- 统一 `baseURL`
- 统一请求头
- 统一 `credentials`
- 统一错误处理
- 统一解析 `{ code, message, data }`

### 5.2 凭证与访客态

默认请求配置必须附带：

```ts
credentials: 'include'
```

原因：

- 后端当前通过 `visitor_id` Cookie 维护匿名访客态
- 简历、面试、知识库等能力依赖该 Cookie 进行访客隔离

前端不得省略该配置。

### 5.3 响应结构处理

前端统一按后端响应包装结构处理：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

约束如下：

- HTTP 成功不等于业务成功
- 必须显式处理 `code`
- 非 200 或业务错误要统一映射为前端领域错误对象

### 5.4 文件上传规则

文件上传统一使用 `FormData`。

适用场景：

- 简历上传
- 知识库上传

上传型交互必须至少具备三态：

- loading
- success
- error

不得出现“点击后无任何反馈”的状态。

## 6. SSE 与流式规范

### 6.1 流式消费方式

统一封装 POST 流式消费器。

原因：

- 当前关键流式接口为 POST
- 不能使用只适配 GET 的 `EventSource` 作为主方案

统一能力要求：

- 发起 POST 请求
- 读取 `ReadableStream`
- 拆分事件块
- 解析 `message` 事件中的 JSON
- 将事件分发给上层业务处理器

### 6.2 事件处理规则

前端必须统一封装事件分发器，禁止在页面层直接用字符串常量散写判断逻辑。

当前面试流式事件包括：

- `status`
- `plan`
- `content`
- `report`
- `step_complete`
- `done`
- `error`

要求如下：

- `content` 用于局部聚合流式正文
- `done` 后必须主动刷新一次会话详情或报告
- `error` 必须保留后端的 `code/message/data`
- 解析失败要能抛出结构化错误，而不是静默吞掉

### 6.3 状态存放位置

流式正文与中间过程状态不得直接写入全局 store。

优先策略：

- 保留在 feature 内局部聚合
- 页面只消费 feature 的结构化结果

## 7. 状态管理规范

### 7.1 服务端状态

服务端数据统一走 `TanStack Query`。

适用对象：

- Skill 列表与详情
- 简历列表与详情
- 面试会话详情
- 面试报告
- 知识检索结果

### 7.2 本地 UI 状态

以下状态保留在组件或 feature 内：

- 表单输入
- 草稿内容
- 对话输入框状态
- 当前流式输出中间态
- 对话区折叠与展开
- 上传中的视觉状态

### 7.3 本地持久化边界

禁止把以下内容只存在 `localStorage`：

- 面试会话历史
- 当前题目进度
- 面试报告事实数据

`localStorage` 仅可用于非事实性偏好：

- 最近选中的 Skill
- UI 折叠态
- 非关键筛选条件

## 8. 样式规范

### 8.1 样式方案

统一使用：

- `CSS Modules`
- `styles/` 中集中维护全局 design tokens

示例内容：

- 颜色变量
- 间距变量
- 圆角变量
- 阴影变量
- 字体层级变量

### 8.2 页面表现约束

- 页面布局先保证桌面端，再覆盖移动端
- 不复刻旧 `static/` 的 DOM 结构
- 保留“面试工作台”产品语义
- 保持功能分区清晰
- 保持交互状态可见

### 8.3 禁止事项

- 禁止引入重量级 UI 框架作为一期前提
- 禁止在业务组件内散写大段行内样式
- 禁止把样式 token 分散定义在多个业务文件里

## 9. 测试规范

测试工具建议：

- 单元/组件测试：`Vitest + React Testing Library`
- API mock：`MSW`

一期至少覆盖以下场景：

- 简历上传成功
- 简历上传失败
- 面试建会话成功
- 面试 SSE 正常流转
- 面试 SSE 错误中断
- 知识库检索空命中
- 知识库检索正常命中
- Skill 列表加载成功
- Skill 详情查看成功

测试目标：

- 验证关键用户路径可用
- 验证错误态有明确反馈
- 验证 API 契约未被前端误读

## 10. 与后端协作规范

### 10.1 契约边界

- 前端字段命名不反向驱动后端模型修改
- 前端不应为了页面方便私自发明后端字段
- 后端无 API 的能力不能在前端假实现

### 10.2 Provider 模块边界

`Provider` 管理在当前阶段标记为：

- 待后端开放完整 API 后接入

因此当前新前端：

- 不落地 `Provider` 管理页面
- 不假设存在完整的 Provider CRUD 能力

### 10.3 知识库边界

当前知识库 API 只支持：

- 上传
- 检索

因此前端一期不能设计为完整的知识库后台管理系统。

### 10.4 新旧前端并存约束

保留 `static/` 期间：

- 新前端不覆盖 `/` 根入口
- 不直接替换现有静态文件
- 通过独立 dev server 或独立部署路径接入

## 11. 已知前置约束

前后端真正分离联调前，必须注意以下问题：

- 后端当前依赖 `visitor_id` Cookie 维护访客态
- 前端必须使用 `credentials: 'include'`
- 后端 CORS 需要从通配源改为显式前端源

如果不先解决上述约束，将会影响：

- 简历列表隔离
- 面试会话归属
- 知识库上传与检索的一致性

## 12. 本阶段不做的内容

本规范对应的当前阶段不包括：

- 不生成 `frontend` 代码骨架
- 不创建 `package.json`
- 不创建 `src/`
- 不创建 `Vite` 配置
- 不接入 React 页面
- 不替换现有 `static/`
- 不改动后端 API
- 不把 `Provider` 管理纳入 v1
- 不把 AIOps 迁入新前端一期范围
